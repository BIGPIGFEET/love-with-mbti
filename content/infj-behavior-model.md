# INFJ 行为模型（Stage 02）

> 依据：[INFJ 网络刻板印象证据台账](../docs/research/infj-stereotype-data.md)。  
> 边界：这是对“网络如何表征 INFJ”的证据约束型创作模型，不是人格诊断、现实个体预测或配对规律。阶段位置、具体触发与修复形式是为本项目四阶段叙事作出的有界创作推断，不代表任何类型必然按该顺序行动。

## 1. 使用规则

- `INFJ-F01` 至 `F08`、`F10`、`F11` 可在窄定义和反例约束下建模；低置信单社区梗 `INFJ-F09` 只用于提醒创作者不要把突然断联合理化，不生成行为、候选事件、分值、道德判断或结局。
- 小红书、Bilibili、知乎中的“强制爱、使用说明书、绿老头、人体扫描仪、最难追”等 `surface_record` 只作为表现风险，不进入行为或候选事件的证据链。
- 关系推进来自具体的询问、披露、边界、兑现、同意和修复。深聊、记住细节、提供帮助、分享隐私、高频联系或短暂沉默都不自动等于好感、承诺、排他或同意。
- 观察和直觉只能形成待核对的假设；共情不能写成准确能力、道德优势、治疗职责或无限情绪劳动。
- 空间和暂停可以是合理需要，但必须与无期限失联、沉默惩罚和逃避责任区分；慢开放也不能成为坚持追逐或越界试探的许可。
- 每个后续场景宜启用 2 至 4 个相邻行为，并让双方至少各有一个合理需要。伤害归因于具体行为及后果，不归因于 INFJ 标签。

## 3. 对玩家行动的预期反应

| 玩家行动 | 可能的建设性效果 | 需要保留的风险或限定 |
|---|---|---|
| 在深入话题前询问意愿，并接受对方今天只想轻松聊天。 | 兼顾意义交流与节奏，提升舒适和继续了解的意愿。 | 愿意深聊不等于恋爱兴趣；拒绝深聊也不等于肤浅。 |
| 面对有限披露，回应已分享内容并询问可谈范围。 | 让隐私和信任同时可见，减少“破解心墙”叙事。 | 玩家不欠无限等待；会影响自身决定的事实仍需适时说明。 |
| 对观察或直觉先核对：“我可能理解错了，你是这个意思吗？” | 给双方修正解释的权利，降低读心和确认偏误。 | 不应利用提问逼供、诊断或反复否定对方的自我陈述。 |
| 明确说出自己需要倾听、建议、实际帮助还是空间，并询问对方容量。 | 让支持方式可协商，减少单向情绪劳动。 | 对方可以没有容量；拒绝当下支持也不能用羞辱表达。 |
| 接住关心行动，同时确认它的意图、自己的接收偏好和触碰边界。 | 降低爱语误读与关系债务，保护双方选择。 | 帮助、礼物和触碰均不能替代同意或承诺确认。 |
| 同意暂停但确认返回时间；若时间变化，要求重新告知。 | 同时保护处理空间、可靠性与后续修复。 | 无限期失联和消息轰炸都会损害关系，安全风险情境另行处理。 |
| 对理想关系愿景回应自己的真实条件，并允许不匹配。 | 把投射转为价值与现实的共同校准。 | 不匹配不代表任何一方不真诚、不成熟或类型不纯。 |
| 直接提出关系定义、排他和未来投入，并承认对方可以不同意。 | 防止深聊、默契和帮助替双方完成承诺。 | 清晰提问不能变成逼迫；犹豫、拒绝和退出都必须被允许。 |

## 4. 冲突维度字典

## 5. 状态语义（复用运行时）

本模型复用 `src/content/schema.ts` 与 `src/game/rules.ts` 的四个状态 ID、初始值、截断、阶段阈值和结局优先级，不做修改。

| state_id | 可观察含义 | 上升表示 | 下降表示 | 应避免的误用 |
|---|---|---|---|---|
| attraction | 对继续了解、共享话题或发展浪漫关系的兴趣。 | 互动增加好奇、欣赏或靠近意愿。 | 探索或浪漫兴趣减弱。 | 不把深聊、记住细节、帮助、回复频率、私人披露或冲突强度自动视为吸引或承诺。 |
| trust | 对诚实、保密、兑现、边界、同意、按约返回和承担影响的信赖。 | 更相信对方会如实说明、尊重范围并完成修复。 | 对动机、可靠性、隐私处理或边界尊重产生疑虑。 | 不用“被看穿”、顺从、无限情绪劳动、秘密数量或被选中感替代信任。 |
| comfort | 当下互动中安全、自在、节奏可承受且无需被类型化的程度。 | 提问、话题、支持、空间和身体边界更可承受。 | 感到被逼问、诊断、攻略、贴标签、越界或忽视。 | 舒适不等于恋爱、排他、触碰同意，也不要求回避所有分歧。 |
| conflict | 未解决误读、失望、边界伤害、防御或悬置责任的累积。 | 读心假设、隐性期待、单向照顾、失联或越界未被修复。 | 张力被说明、核对、承担、协商或实际修复。 | 冲突低不等于一方长期压抑需要、总在倾听或不敢拒绝。 |

## 6. Stage-02 交接标准

- 候选事件见 [INFJ 候选事件库](scenes/infj-candidate-scenes.md)。
- 上游 ID 集为行为 `INFJ-B01` 至 `INFJ-B12`、特征 `INFJ-F01` 至 `F08`、`F10`、`F11`、候选事件实际引用的合格 `evidence_source`、冲突 `INFJ-K01` 至 `INFJ-K10`，以及四个运行时状态 ID。
- `INFJ-F09` 与所有 `surface_record` 保持机械惰性；它们只能在风险说明中防止“提门、强制爱、使用说明书、读心、命定伴侣”等包装渗入后续玩法。
- Stage 03 只负责筛选、排序和分配独立 `scene_id`；对白、选项、即时反馈、数值变化、阈值与结局均不属于本阶段。
- 正式筛选时应覆盖四阶段，并至少保留一次：深聊前的节奏确认、观察后的询问校验、支持方式协商、及时表达边界、带返回协议的暂停、暂停后的修复，以及关系意图的明确确认。
