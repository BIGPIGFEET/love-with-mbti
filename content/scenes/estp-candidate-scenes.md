## Stage-02 审计

### 1. 证据与分类

- 13 个行为和 18 个候选均直接携带特征与合格 evidence_source ID；候选来源未使用 surface_record 或 lead。
- ESTP-F09 只在 C04、C14 的具体风险分级和 C18 的反标签语境出现，没有将极端冒险变成奖励机制。
- ESTP-F10 只出现在 C18，用于拆解“坏男孩、花心玩家、墨镜哥、莽夫、派对动物”等投射；标签本身机械惰性。
- ESTP-S42 只支持平台文案中“自由”和“专一”并置；候选没有把它当作忠诚、承诺能力或关系结果证据。
- 百分比、排行、临床化标题、性别化坏男孩包装和知乎强概括回答没有进入候选 source IDs。

### 2. 阶段推进

- first_meeting 只处理即兴安排、社交节奏、直接玩笑和低风险体验，不预设触碰、深层披露、排他或承诺。
- contact 引入计划变化、支持方式、快速补救、亲近信号和表达透明度，但仍不把频繁联系与帮助视为关系定义。
- familiarity 才进入反复失约、具体示爱边界、情绪错位修复、暂停—返回和高成本共同体验。
- ambiguity 才讨论关系范围、排他、未来投入、面向多人的社交信号与坏男孩类型投射。

### 3. 去重

- C01 与 C05 都含即兴：C01 是初见突发地点变化与参与节奏，C05 是联系后已有约定被新活动挑战。
- C04 与 C14 都含风险：C04 是初见低成本试行与拒绝压力，C14 是熟悉后高成本、长时或身体负担投入。
- C06 与 C12 都含支持：C06 是尚未错位时询问支持方式，C12 是方案和玩笑已经让玩家感觉未被听见后的修复。
- C03、C08 与 C17 都含信号：C03 是初见玩笑边界，C08 是联系期多通道亲近含义，C17 是暧昧期社交信号、排他与事实一致性。
- C07 与 C10 都含可靠性：C07 是单次突发补救的共同知情，C10 是重复变更形成的长期成本。
- C15 与 C16 分别处理当前关系范围和未来资源确定性，不把关系定义与长期计划合并。

### 4. 玩家能动性与安全

- 每个候选都允许玩家接受、拒绝、澄清、提出条件、暂缓或退出；拒绝社交、冒险、建议、触碰、礼物、计划变化和承诺不会被自动惩罚。
- “全部跟随、永远觉得玩笑有趣、维持刺激、接受所有帮助、回避关系定义”都不是万能策略；玩家的节奏、安全、事实知情和现实不兼容同样有效。
- TA 的行动力、直接和自由不能为擅自决定、玩笑越界、失约、情绪淡化、欺骗、突然失联或背叛免责。
- 玩家对不忠和风险的担忧也不能合理化监控、控制、人格羞辱、精神诊断或要求 TA 表演刻板人设。
- 所有亲密与承诺信号都落到具体同意和协议，未把消息频率、共同活动、帮助、礼物、触碰或热烈表达自动换算成排他与承诺。

### 5. 当前缺口与下游边界

- 本库没有锁定十题、分配任何 scene_id、撰写对白或选项，也没有设置状态数值、阈值或结局；候选编号和排列不代表正式顺序。
- 中文第一人称证据仍窄；小红书完整正文是未说明身份与方法的类型文案，知乎材料包含窄自述、单一样本观察和强概括回答。下游不得声称代表大陆或华语 ESTP。
- 当前生产注册表没有 ESTP，且不存在 ESTP 题目与结局。Stage 03 可以继续筛选设计序列，但“已可玩”需要以后单独完成生产内容、注册和运行时验证。

### 6. 当前版本引用验收

- 每个来源使用完整 ESTP-Sxx ID；每个候选的 feature IDs 与 source IDs 是其 behavior IDs 对应集合的并集，避免来源缩写或同步遗漏。并集只表示可追溯输入，不表示每个来源都支持候选的全部具体细节。
- 每个候选至少包含一个冲突 ID、一个运行时状态 ID、具体触发、可观察 NPC 行为、玩家决策压力、能动性声明和叙事护栏。
- 具体场景、关系阶段、可逆试验、关系协议和修复动作均为有界创作推断，没有伪装成社区观察。
- Stage 03 只从本库筛选正式顺序；本阶段不创建正式场景 ID、题目、选项、效果、阈值或结局。
