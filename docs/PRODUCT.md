## 1. 执行摘要

Love with MBTI 是一款以 MBTI 网络文化为传播入口、以关系选择为核心玩法的轻量网页文字游戏。玩家以自己的身份，与一个由网络流行印象整理和创作而成的 MBTI 模拟对象互动，在十次逐步升级的关系事件中作出选择，并根据吸引、信任、舒适和冲突四项状态进入不同关系结局。

产品的重点不是判断玩家“适合哪种人格”，也不是提供恋爱或心理诊断，而是把抽象的性格标签转化为具体、可回应且存在真实代价的相处情境。玩家应当感受到角色的类型辨识度、选择的两难性、结果的可解释性，以及重玩和讨论不同路径的乐趣。

一句话价值主张：

> 用十次现实又略带荒诞的相处选择，看看你和一种 MBTI 网络印象会把关系走到哪里。

当前版本是无需账号和后端的纯前端静态应用，已经开放：

`INTJ`、`ENTJ`、`ESTJ`、`ENTP`、`ENFP`、`ENFJ`、`INTP`、`INFJ`、`INFP`、`ISFJ`、`ISFP`

每种开放类型拥有独立的十题内容、结局文案、关系评价和模糊反馈，并共用统一的关系数值、阶段门槛和结局判定规则。

## 2. 产品定义

### 2.1 产品名称与品类

- **名称：** Love with MBTI
- **品类：** 娱乐向网页互动文字游戏
- **载体：** 移动端优先、兼容桌面浏览器的单页 Web 应用
- **单局结构：** 固定 10 题、每题 4 个选项，允许中途结束
- **建议时长：** 约 8～12 分钟
- **当前模式：** 免费体验，无需登录

### 2.2 产品本质

产品把一种 MBTI 网络印象拆解为连续的关系事件。玩家不是回答抽象人格问题，而是在约会、沟通、边界、信任、支持、冲突和承诺等具体场景中表达自己的处理方式。

剧情反馈和数值系统共同决定关系走向：

- 剧情负责让玩家理解 TA 为什么产生某种反应；
- 数值负责保持跨题目的状态连续性和判定一致性；
- 结局负责回收玩家此前的选择，并给出可理解、可比较的结果。

### 2.3 产品不是什么

Love with MBTI 不是：

- MBTI 人格测试或类型识别工具；
- 心理诊断、恋爱能力评估或现实关系建议系统；
- 对某一 MBTI 群体的科学结论或准确人物画像；
- 用单一标签预测真实个体行为的工具；
- 拥有固定姓名、性别、职业、身世和成长线的传统恋爱角色游戏；
- 以“选出标准答案”为目标的知识问卷。

## 3. 产品背景与机会

MBTI 网络内容具有低理解门槛、强标签辨识度和天然讨论性，但常见内容往往停留在静态描述、梗图或结果型测试。Love with MBTI 的产品假设是：用户不只想阅读“某类型是什么样”，还愿意进入具体关系情境，通过自己的选择观察互动如何变化。

产品希望解决三类体验缺口：

1. **从标签到行为：** 把抽象标签转化为可以感受、回应和讨论的具体事件。
2. **从结果到过程：** 不只给出结论，而是让玩家看见关系如何被一连串选择推动。
3. **从唯一答案到真实取舍：** 让多个选项各有合理动机和代价，避免把游戏变成讨好角色的攻略题。

上述内容是产品设计假设，不代表已经通过大规模用户研究或统计数据验证。

## 4. 产品目标与非目标

### 4.1 核心目标

1. **低门槛完成一局**
   用户无需阅读外部说明，即可理解类型选择、答题、反馈和结局流程，并在约十分钟内完成一次体验。

2. **形成鲜明但不过度绝对化的类型体验**
   每个模拟对象应具有可辨识的网络文化特征，同时明确它是娱乐化创作，不代表现实中的所有同类型人格。

3. **让选择具备真实取舍**
   每题至少存在两个看似合理但代价不同的方向；不能通过持续顺从、持续坦诚或固定点击某个位置稳定获得最好结果。

4. **让结果可解释**
   中途结束和最终结局必须能够回溯到具体选择、即时反馈和四维关系状态，避免随机惩罚感。

5. **促进重玩、比较和讨论**
   不同类型、选项策略和结局应提供足够差异，使玩家愿意重新挑战、比较路径或分享当前页面。

6. **建立可扩展的内容生产体系**
   新类型应能沿用统一的研究、行为建模、场景筛选、题目写作、结局设计、路径平衡和运行时接入流程。

### 4.2 当前非目标

- 登录、账号、云存档或跨设备进度；
- 服务端排行榜、玩家排名或虚构胜率；
- 玩家自身 MBTI 的收集、匹配统计或兼容性结论；
- 随机题库、分支地图或长线角色养成；
- 角色姓名、立绘、语音、背景音乐和复杂演出；
- 广告、订阅、内购或其他付费系统；
- 基于真实个体数据的心理或关系判断；
- 直接把网络讨论频率描述为人口统计事实。

这些能力未来可以作为独立假设评估，但不属于当前版本承诺。

## 5. 目标用户

### 5.1 核心用户

熟悉或接触过 MBTI 网络文化、喜欢关系话题和轻量互动内容的年轻互联网用户。他们通常在手机或桌面浏览器中利用碎片时间完成一局，并期待：

- 快速理解玩法，不需要学习复杂规则；
- 在具体相处情境中表达自己的选择；
- 看到鲜明、有趣且不完全可预测的角色反应；
- 理解自己为什么得到当前结果；
- 比较不同类型、不同选择或朋友的结局；
- 获得适合讨论和分享的文案。

### 5.2 次级用户

- 对 MBTI 不熟悉，但喜欢互动小说或选择题游戏的用户；
- 对关系沟通、边界和价值取舍感兴趣的用户；
- 希望将游戏作为朋友、伴侣或社交群体讨论话题的用户。

### 5.3 核心用户任务

当用户想体验一种 MBTI 关系想象时，产品应帮助其：

1. 快速选择感兴趣的模拟对象；
2. 在短时间内进入具体关系事件；
3. 通过有意义的选择表达自身倾向；
4. 观察即时反应和关系变化；
5. 获得能解释过程的关系结局；
6. 方便地重玩、切换类型或分享链接。

### 5.4 典型使用场景

- 在社交媒体或朋友分享的链接中首次进入；
- 独自游玩并尝试获得不同结局；
- 与朋友或伴侣比较面对同一场景时的选择；
- 因某种 MBTI 标签产生兴趣，主动选择对应类型体验；
- 完成一种类型后返回选择页继续挑战其他类型。

## 6. 产品定位与差异化

### 6.1 定位

Love with MBTI 定位为“MBTI 网络文化 × 关系情境选择 × 可解释结局”的轻量互动产品。

它借用 MBTI 的认知入口，但真正的游戏对象是相处过程中的选择与后果。类型标签负责建立预期，场景负责制造冲突，玩家选择负责表达立场，关系系统负责保持连续性，结局负责形成记忆点。

### 6.2 核心价值

| 价值 | 产品表达 |
| --- | --- |
| 易进入 | 无需注册，打开网页即可选择类型并开始 |
| 有辨识度 | 每种类型拥有独立的行为模型、场景、反馈和结局文案 |
| 有取舍 | 选项体现不同合理需求，不把顺从或“高情商话术”设为万能答案 |
| 可理解 | 即时反应解释影响，结局页展示准确关系状态 |
| 可重玩 | 多类型、多结局和不同策略形成重复体验价值 |
| 可讨论 | 场景、黑色幽默和结局文案适合比较与分享 |

### 6.3 体验差异

- 相比人格测试：关注关系决策过程，而不是给玩家贴类型标签。
- 相比静态 MBTI 内容：允许玩家回应角色，并承担选择后果。
- 相比传统恋爱游戏：弱化人物身世与美术资产，强化关系事件、边界和价值取舍。
- 相比数值攻略：过程隐藏精确分数，避免把叙事简化为加减分计算。

## 7. 体验设计原则

1. **叙事先于数值**
   玩家首先理解场景、TA 的表达和冲突，再接触关系状态；数值不能抢过叙事主线。

2. **选择必须有代价**
   好选项不等于没有损失。一次回应可以增加信任，同时降低吸引或提高短期冲突。

3. **没有跨场景万能策略**
   顺应、坦诚、协商、冒险或正面冲突只描述处理方向，不直接对应固定好坏。

4. **过程模糊，结果透明**
   答题过程中只展示趋势和强度；结局页再展示准确数值，兼顾沉浸感与结果解释。

5. **失败也是完整内容**
   中途结束不是错误页面。它必须有明确原因、符合角色边界，并提供重新挑战和返回入口。

6. **鲜明但不污名化**
   可以使用克制的夸张和黑色幽默，但不能把人格类型等同于精神疾病、道德缺陷或危险人格。

7. **短局但有关系进展**
   十题必须形成从初识到暧昧的升级过程，而不是十道互不相关的测试题。

8. **规则一致，内容因类型而异**
   所有类型共用稳定的状态和结局合同；具体偏好、雷区、反馈和叙事必须来自各自的内容依据。

## 9. 用户旅程与信息架构

### 9.1 核心流程

```text
进入网站
  ↓
查看娱乐化声明并选择已开放类型
  ↓
阅读关系场景、TA 原话和问题
  ↓
从四个回应中选择一个
  ↓
更新四维状态并判定是否结束
  ↓
查看 TA 的即时反应与模糊变化提示
  ├─ 未结束：进入下一题
  └─ 已结束：进入结局页
                 ↓
        查看结局、原因与准确数值
                 ↓
       重新挑战 / 复制链接 / 返回选类型
```

### 9.2 页面职责

| 页面 | 核心任务 | 必要信息与操作 |
| --- | --- | --- |
| 类型选择页 | 选择模拟对象 | 已开放类型、类型简介、开始按钮、筹备中状态、娱乐化声明 |
| 题目页 | 理解场景并作出选择 | 当前阶段、题目进度、场景、TA 原话、问题、4 个选项、模糊关系计、返回 |
| 反馈页 | 理解选择产生的影响 | 已选回应、TA 即时反应、1～2 条模糊变化提示、当前关系计、继续 |
| 结局页 | 理解并处理本局结果 | 结局标题、核心文案、具体原因、准确四维数值、关系评价、重新挑战、复制链接、返回 |

### 9.3 关键交互要求

- 玩家选择后不能跳过即时反馈直接进入下一题；
- 每次选择必须先结算数值，再执行结束判定；
- 中途结束也必须经过反馈页，使结果与刚才的选择建立因果关系；
- 返回类型选择或切换类型时必须重置本局状态；
- 重新挑战保留当前类型，但重置题目和四维状态；
- 分享功能当前只复制页面链接，不生成未经实现的分享卡或统计文案；
- 禁用类型必须明确显示“筹备中”，并提供可理解的无障碍名称。

## 11. 核心玩法与规则

本节提供产品层摘要。精确运行时行为以 `src/game/rules.ts` 和 `src/content/schema.ts` 为准。

### 11.1 四维关系状态

| 维度 | 初始值 | 含义 | 有利方向 |
| --- | ---: | --- | --- |
| 吸引 | 25 | TA 对玩家的兴趣与恋爱火花 | 越高越好，但不能替代信任和舒适 |
| 信任 | 25 | TA 是否认为玩家真诚、可靠并尊重边界 | 越高越好 |
| 舒适 | 25 | TA 与玩家相处时是否自然和放松 | 越高越好 |
| 冲突 | 10 | 累积摩擦、敌意和关系压力 | 越低越平静 |

所有状态限制在 `0～100`。

### 11.2 阶段结构

| 题目 | 阶段 | 进入下一阶段的条件 |
| --- | --- | --- |
| Q01～Q02 | 初识 | 吸引≥25、信任≥20、舒适≥20、冲突≤20 |
| Q03～Q05 | 接触 | 吸引≥35、信任≥30、舒适≥25、冲突≤45 |
| Q06～Q08 | 熟悉 | 吸引≥45、信任≥40、舒适≥35、冲突≤45 |
| Q09～Q10 | 暧昧 | Q10 后进入最终分类 |

阶段只能逐级推进，不能倒退或跳级。“相恋”不是答题阶段，只能作为最终结果。

### 11.3 判定顺序

每次选择后的固定顺序：

1. 应用选项对四维状态的影响；
2. 将各维状态限制在 `0～100`；
3. 检查全局强制结束；
4. 在 Q02、Q05、Q08 检查阶段门槛；
5. 若到 Q10 且没有提前结束，执行最终结局分类。

同一步命中多个条件时，只采用优先级最高的结果。

### 11.4 中途结束

全局结束优先级：

1. 冲突≥80：当场决裂；
2. 舒适≤5：强烈不适；
3. 信任≤5：彻底失信。

阶段门槛结束：

- Q02 未达标：没有下次见面；
- Q05 未达标：渐渐失联；
- Q08 未达标：止于熟人。

吸引降到 0 不会单独触发提前结束，因为双方仍可能发展为朋友。

### 11.5 最终结果

完成 Q10 后按固定优先级进入：

1. 形同陌路；
2. 确认恋爱，并细分为稳定发展或已经埋下隐患；
3. 危险恋人；
4. 成为朋友；
5. 暧昧未决。

精确阈值属于共享规则，不应在类型内容中单独覆盖。类型差异应通过场景、选项效果、反馈和结局文案表达。

## 12. 内容设计要求

### 12.1 角色定义

每个攻略对象都是目标 MBTI 的“网络流行印象模拟对象”，而不是对真实人格的完整复刻。

角色应当具备：

- 来自多来源网络讨论的高频或有代表性的行为印象；
- 能在关系情境中自然表现的偏好、边界和雷区；
- 跨十题相对稳定的回应逻辑；
- 足够辨识度，以及服务于游戏表达的克制夸张；
- 明确区分研究观察、创作推断和戏剧化加工的内容依据。

角色不得具备：

- 固定姓名、年龄、职业、性别和恋爱取向；
- 为解释行为而虚构的童年、家庭、创伤或疾病；
- 被包装成心理学事实的网络段子；
- 用单一 MBTI 标签合理化控制、羞辱、骚扰或其他伤害行为。

统一使用“TA”或“对方”指代角色。

### 12.2 内容研究要求

每种新类型在正式写题前应完成独立研究。研究对象是“网络如何描述和想象该类型”，而不是证明描述具有心理学真实性。

研究应：

- 同时收集自述、他人评价、关系讨论、正反面观点和反刻板印象；
- 优先覆盖多个相互独立的来源和平台；
- 区分高频特征、特定情境特征和戏剧化梗；
- 记录来源、语境、来源类型、重复程度、关系相关性、冲突潜力和不确定性；
- 不用单一帖子或营销内容支持核心角色特征；
- 不把平台出现频率推断为现实人群比例；
- 为每个正式场景保留可追溯的研究与行为依据。

ENTP 研究计划是首个内容包的方法样本，后续类型应采用统一流程，但不能直接复制 ENTP 的特征和冲突。

### 12.3 十题叙事结构

| 阶段 | 内容目标 |
| --- | --- |
| 初识 | 建立第一印象，测试双方是否愿意继续了解 |
| 接触 | 展示类型核心行为模式与日常相处摩擦 |
| 熟悉 | 引入边界、信任、支持和价值观冲突 |
| 暧昧 | 处理承诺、关系定义、未来安排和最终取舍 |

十题必须构成逐步升级的关系体验。相邻题目之间应有强度、亲密度或责任范围上的推进。

### 12.4 场景与冲突

每道题至少包含：

- TA 当前合理但带有类型特征的诉求；
- 玩家可能在意的另一种合理需求；
- 无法被一个无代价答案同时满足的冲突；
- 选择后能够被剧情和数值共同解释的后果。

不得使用：

- 没有关系压力的普通偏好题；
- 一个明显文明选项加三个纯粹冒犯选项；
- 持续顺从即可稳定通关的讨好结构；
- 为强调类型辨识度而让 TA 无理由地愚蠢、恶毒或失去基本社会能力；
- 只更换 MBTI 名称、没有行为差异的跨类型复用场景。

### 12.5 选项策略与数值

运行时允许五类策略标签：

- `accommodate`：顺应或配合；
- `honest`：坦诚表达；
- `negotiate`：协商条件与共同决策；
- `risky`：冒险、玩笑、试探或回避；
- `confront`：直接对抗、追问或施压。

每题只展示 4 个选项，不要求每题覆盖全部 5 类策略。策略标签只用于分析，不直接决定分数。

选项要求：

- 同题至少有两个看似合理、代价不同的选择；
- 选项位置不能长期对应固定策略或固定好坏；
- 措辞、效果和即时反馈必须针对当前场景；
- 允许少量明显危险的黑色幽默选项，但不能机械地每题设置一个“送命答案”；
- 每个选项可以同时带来正面收益和负面代价。

数值约束：

- 单维变化只允许 `-20、-15、-10、-5、0、5、10、15、20`；
- 四维绝对变化总和不得超过 `60`；
- 普通选项建议不超过 `40`；
- `|15|` 或 `|20|` 属于高强度变化，原则上不超过两个维度；
- 超过建议预算但未超过硬限制的选项必须作为平衡警告复核，并有明确叙事理由。

### 12.6 反馈与结局文案

玩家选择后必须展示：

1. **TA 的即时反应：** 回应玩家实际说法，符合当前类型的行为逻辑，并用一到三句解释影响；
2. **模糊变化提示：** 用方向和强度描述 1～2 个主要变化，不显示准确数值。

结局内容必须：

- 说明关系为什么走到当前状态；
- 对应稳定结局语义，不因类型不同而改变规则含义；
- 批评具体行为而不是诊断或贬低玩家本人；
- 在确认恋爱时区分稳定发展和隐藏风险；
- 保持足够鲜明、简洁和可分享，但不牺牲因果解释。

### 12.7 文案与伦理边界

- 语气清新、简洁、口语化，允许克制的黑色幽默；
- 不使用侮辱、歧视、心理疾病或性别刻板印象制造笑点；
- 不把控制、羞辱、骚扰或持续越界美化为高情商攻略；
- 不暗示某种 MBTI 必然具有某种行为；
- 不声称游戏结果证明玩家的恋爱能力或现实兼容性；
- 游戏内持续保留娱乐化声明。

## 13. 内容生产流程

新类型应遵循以下受控流程：

```text
网络话语研究与证据台账
  ↓
中立特征与行为模型
  ↓
候选关系事件库
  ↓
正式十题选择与阶段排序
  ↓
选项、效果、反馈与追溯记录
  ↓
结局、关系评价与模糊反馈
  ↓
完整路径枚举与平衡复核
  ↓
迁移到正式 TypeScript 内容包
  ↓
自动化测试、人工试玩与发布
```

各阶段必须保留稳定 ID 和来源映射。研究资料、行为模型、正式场景、运行时题目和结局之间不得只靠文件顺序或人工记忆关联。

已接入不代表内容永远完成。每种类型的证据强度、文案成熟度和平衡状态需要独立维护；共享规则变更则必须重新验证全部开放类型。

## 14. 信息与视觉设计要求

### 14.1 视觉方向

创意基准是“关系事件记录单”：以温暖纸张、松墨文字、陶土橙和灰青绿形成可翻阅、可批注的关系记录感。

产品层要求：

- 单一主纸面贯穿类型选择、题目、反馈和结局；
- 场景与 TA 原话的视觉优先级高于状态解释；
- 四维关系计始终作为一组出现；
- 通过纸色、细线和虚线建立层级，避免通用仪表盘式卡片堆叠；
- 主操作明确，次要操作不过度竞争；
- 不使用未经证实的胜率、排名或“超过多少玩家”等展示。

精确颜色、排版、间距和组件规则以 `DESIGN.md` 为准。

### 14.2 响应式要求

- 移动端优先，同时支持常见桌面宽度；
- 长叙事使用单栏，四个选项保持连续、易扫描；
- 手机端按钮和导航应保留足够点击区域；
- 文字换行不能遮挡阶段、关系计或主要操作；
- 类型列表需要清楚区分已开放与筹备中状态。

### 14.3 无障碍要求

- 所有操作均可通过键盘完成；
- 焦点状态清晰可见；
- 文字与背景保持足够对比度；
- 不依赖颜色作为状态好坏的唯一表达；
- 关系计提供文字标签、方向说明和原生进度语义；
- 禁用类型、图标按钮和返回操作具有可理解的无障碍名称；
- 尊重 `prefers-reduced-motion`；
- 复制链接失败时提供文字提示和人工操作方法。

## 15. 技术与数据约束

### 15.1 技术栈

- React 19
- React DOM 19
- TypeScript 5.9
- Vite 7
- Vitest 3
- Testing Library
- jsdom

### 15.2 架构要求

- 应用保持为无账号、无后端依赖的静态单页应用；
- 单局状态仅在当前浏览器页面生命周期内维护；
- 每个类型通过统一 `ContentPack` 合同注册；
- 关系规则由共享模块统一实现，不在组件或类型内容中重复判定；
- 内容数据、展示组件和规则计算保持分离；
- 新类型必须先通过 schema 校验再进入可选列表；
- 不得在没有可靠数据来源时展示玩家统计或比较指标。

### 15.3 当前性能注意事项

当前生产构建可成功完成，但单个 JavaScript chunk 已出现超过 500 kB 的非阻塞警告。继续增加内容包时，应评估按类型动态加载或拆分内容，避免所有类型数据一次性进入首屏包。

## 16. 质量标准与验收

### 16.1 功能验收

- 用户能够完成选择类型、答题、反馈、结局和重玩流程；
- 11 种开放类型均加载正确内容包；
- 所有筹备中类型不可误进入游戏；
- 状态更新、阶段门槛和结局优先级与共享规则一致；
- 返回、重玩和切换类型不会保留上一局状态；
- 复制链接成功或提供明确失败提示。

### 16.2 内容验收

- 每个内容包完整包含 10 题、40 个选项和全部稳定结局内容；
- 每题均有场景、TA 原话、冲突维度、研究引用、标签和设计说明；
- 选项效果使用合法档位并满足硬预算；
- 即时反馈与选项实际效果一致；
- 十题形成合理的关系升级；
- 不存在跨十题无条件支配其他策略的万能套路；
- 所有高强度或超建议预算选项均经过叙事与平衡复核；
- 内容遵守娱乐化声明、角色边界和反污名化要求。

### 16.3 工程验收

发布前至少执行：

```bash
npm run check
npm test
node scripts/validate-content.mjs
node scripts/analyze-question-paths.mjs
npm run build
```

共享规则修改需要重新分析全部开放类型；单个类型内容修改至少重新验证该类型，并执行全项目回归。

截至 2026-09-04，当前基线为：

- TypeScript 检查通过；
- 16 个测试文件、84 项自动化测试通过；
- 11 个内容包结构校验通过；
- 每种类型完成 `4^10 = 1,048,576` 条等权选择路径枚举；
- 生产构建通过；
- 部分选项仍有超过建议数值预算的非阻塞警告。

路径枚举用于规则压力测试和结局覆盖验证，不等同于现实玩家选择概率，也不能替代人工试玩。

## 17. 成功标准与验证计划

### 17.1 当前可执行的成功标准

在尚未接入真实用户统计前，以任务完成和定性试玩为主：

- 新用户无需外部说明即可开始并完成一局；
- 一局通常可在 8～12 分钟内完成；
- 玩家能够说出所选类型的可辨识特征；
- 玩家能够解释自己为何进入当前结局；
- 玩家认为至少大部分题目存在真实取舍，而非明显正确答案；
- 中途结束能被理解为选择后果，而非随机惩罚；
- 玩家愿意重玩、切换类型、比较选择或分享链接；
- 不同用户不会一致认为某个固定策略或选项位置是万能解。

这些标准需要通过可用性测试和访谈验证，不能仅凭路径枚举证明。

### 17.2 后续建议指标

若未来接入合规、匿名且透明的基础统计，可关注：

| 维度 | 建议指标 | 用途 |
| --- | --- | --- |
| 可理解性 | 开始率、首题完成率、流程错误率 | 判断入口和操作是否清楚 |
| 完成体验 | 单局完成时间、到达结局页比例 | 判断节奏和长度是否合适 |
| 重玩价值 | 同会话重开率、类型切换率 | 判断路径和多类型吸引力 |
| 分享价值 | 复制链接操作率 | 判断结果是否值得传播 |
| 内容质量 | 各题选项分布、提前结束点分布 | 发现明显诱导或失衡 |
| 结果质量 | 结局分布、结局解释满意度 | 检查规则与文案是否可理解 |

任何统计功能上线前必须明确数据范围、匿名化方式、保存期限、用户告知和删除机制。没有足够样本量时，不展示排名、百分位或兼容性结论。

## 18. 风险与应对

| 风险 | 表现 | 应对原则 |
| --- | --- | --- |
| 刻板印象被当成事实 | 用户把角色行为理解为真实群体结论 | 持续展示娱乐化声明，区分证据、网络话语和创作加工 |
| 类型角色同质化 | 不同类型只是替换标签和文案 | 为每种类型建立独立研究、行为模型、冲突覆盖和反馈逻辑 |
| 选项存在明显优解 | 玩家只寻找固定攻略套路 | 路径枚举、策略支配检查和人工试玩共同验证 |
| 数值压过叙事 | 玩家只按进度条优化分数 | 过程隐藏精确数字，用剧情解释主要变化 |
| 失败产生惩罚感 | 中途结束显得突兀或不公平 | 先展示即时反馈，再进入能解释原因的结局 |
| 等权模型误导 | 把自动枚举分布当作真实用户概率 | 报告中明确模型用途，真实结论依赖用户数据 |
| 内容规模拖累性能 | 类型增加导致首屏包继续膨胀 | 监控构建体积，评估按类型动态加载 |
| 范围持续扩张 | 过早加入账号、排名、随机题库等系统 | 新能力必须先定义用户问题、成本、数据要求和验收指标 |
| 数据与隐私风险 | 未来收集玩家类型或行为数据 | 默认少收集，先完成隐私设计和明确告知 |
